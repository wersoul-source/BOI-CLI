# แผน BOI Web UI (หน้าเว็บสำหรับสั่งงาน BOI)

สถานะ: **ข้อเสนอ** รอผู้สร้าง BOI อนุมัติ

## เป้าหมาย

ผู้ใช้เปิดเบราว์เซอร์ พิมพ์คำสั่ง และ BOI ทำงานบนเครื่องเดียวกับที่ CLI รัน โดยได้ความสามารถเท่ากับ TUI ทุกอย่าง
ได้แก่ เห็นความคืบหน้า กดอนุมัติหรือปฏิเสธการเขียนไฟล์และการรันคำสั่ง ยกเลิกงาน และดูว่า Agent ประกอบจาก Block อะไร

## ทางที่เลือก

เพิ่มคำสั่ง `boi web` ซึ่งเปิด web server ในตัว binary เดิม แล้วต่อเข้ากับ Runtime ตัวเดียวกับที่ TUI ใช้
(`app.BuildAgent` และ `Service.Start`)

```text
เบราว์เซอร์ ──HTTP/SSE──► boi web (127.0.0.1) ──► app.BuildAgent ──► Service.Start
     ▲                                                     │
     └──────────── event: ขั้นตอน, ขออนุมัติ, ผลลัพธ์ ◄──────┘
```

### เหตุผลที่ไม่เรียก `boi ask` ทีละคำสั่ง

`boi ask` ออกแบบมาสำหรับ automation จึงปฏิเสธทุกอย่างที่ต้องขออนุมัติ
ถ้าหน้าเว็บส่งงานผ่าน `boi ask` ผู้ใช้จะไม่มีทางอนุมัติการเขียนไฟล์ได้เลย
ส่วน `Service.Start` ส่ง event ออกมาเป็นลำดับอยู่แล้ว รวมถึงคำขออนุมัติที่รอคำตอบ
ซึ่งเป็นกลไกเดียวกับที่ TUI ใช้ หน้าเว็บจึงเป็นแค่หน้าจออีกแบบของเครื่องยนต์เดิม

### เหตุผลที่ไม่ฉาย TUI ลงเบราว์เซอร์ (แบบ ttyd + xterm.js)

ทำได้เร็วกว่า แต่บนมือถือพิมพ์คีย์ลัดอย่าง `A` `R` `Esc` ลำบาก
และต้องเพิ่ม dependency สำหรับจำลอง terminal ส่วนหน้าเว็บจริงใช้ปุ่มได้ เหมาะกับที่ผู้ใช้สั่งงานจากมือถือ

## ความปลอดภัย (ต้องมีตั้งแต่วันแรก)

- รับการเชื่อมต่อเฉพาะ `127.0.0.1` เท่านั้น ถ้าจะใช้จากเครื่องอื่นต้องผ่าน SSH tunnel
- ทุกครั้งที่เริ่ม สุ่ม token ใหม่ และแสดงลิงก์พร้อม token ใน terminal เบราว์เซอร์ต้องส่ง token มาทุกคำขอ
- ตรวจ `Origin` และ `Host` เพื่อกันเว็บอื่นแอบยิงคำสั่งเข้ามา (CSRF, DNS rebinding)
- การอนุมัติผูกกับ fingerprint ของคำสั่งเหมือนใน TUI ไม่มีปุ่ม "อนุมัติทั้งหมด"
- ไม่ส่ง API key หรือค่า `PSC_*` ไปที่หน้าเว็บ

## ลำดับงาน

แต่ละขั้นเป็น PR เดียว และ revert ได้

| ขั้น | งาน | เสร็จเมื่อ |
|---|---|---|
| W1 | `boi web` เปิด server ที่ localhost พร้อม token และหน้าเว็บเดียว (Go `embed` ไม่มี build step) พิมพ์คำสั่งแล้วเห็นคำตอบ | ถามงานอ่านไฟล์จากเบราว์เซอร์แล้วได้ผลเหมือน TUI มี test ปฏิเสธคำขอที่ไม่มี token หรือมาจาก origin อื่น |
| W2 | สตรีม event แบบ SSE: ขั้นตอน, Tool ที่เรียก, ผลลัพธ์ และปุ่มยกเลิก | ปุ่มยกเลิกหยุดงานได้ภายใน 1 วินาที และหน้าเว็บแสดงขั้นตอนตามลำดับ |
| W3 | แผงอนุมัติ: แสดงสิ่งที่จะเขียนหรือรัน พร้อมปุ่มอนุมัติและปฏิเสธ | การเขียนไฟล์ต้องรอการกดอนุมัติ ถ้าหมดเวลาถือว่าปฏิเสธ มี test ตรวจ fingerprint |
| W4 | หน้าแสดงสถานะ: ผลของ `boi env`, Provider, preset และปุ่มเปลี่ยน preset | ข้อมูลตรงกับ `boi env --json` |
| W5 | ประวัติงาน: เปิด manifest ใน `agent-folder/output` ได้ | เปิดผลงานเก่าได้จากหน้าเว็บ |

## สิ่งที่ไม่ทำในรอบนี้

- ผู้ใช้หลายคนพร้อมกัน, การล็อกอิน, เปิดให้เข้าจากอินเทอร์เน็ต
- แก้ไขไฟล์ผ่านหน้าเว็บโดยตรง
- framework ฝั่งหน้าเว็บ ใช้ HTML, CSS และ JavaScript ล้วนในไฟล์เดียว

## ความเสี่ยงหลัก

หน้าเว็บที่เปิดค้างไว้คือช่องทางสั่งให้เครื่องรันคำสั่งได้
ถ้าข้อ localhost, token และ Origin ข้อใดข้อหนึ่งหลุด เว็บอื่นที่ผู้ใช้เปิดในเบราว์เซอร์เดียวกันจะสั่ง BOI ได้
จึงต้องมี test สามข้อนี้ตั้งแต่ W1 ก่อนจะมีปุ่มอนุมัติใน W3
